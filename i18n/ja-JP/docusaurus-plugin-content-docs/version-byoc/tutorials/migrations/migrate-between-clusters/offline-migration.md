# オフライン移行

オフライン移行は、ソースの Zilliz Cloud クラスターからターゲットの Zilliz Cloud クラスターへ、既存の全データを転送します。この方法は、同一組織内および異なる組織間の移行をサポートします。計画メンテナンスや小規模なデータベース移行など、一時的な書き込み中断が許容されるシナリオに最適です。

<Admonition type="info" icon="📘" title="Notes">

カットオーバー中にアプリケーションがソースクラスターへの書き込みを続けると、ターゲットクラスターが新しいエンティティ（特に移行ジョブ完了後に挿入されたエンティティ）を見落とす可能性があります。ターゲットデータを完全に保つには、カットオーバーウィンドウを設定し、ソースクラスターへの書き込みを停止し、移行ジョブが完了するのを待ち、ターゲットクラスターを検証し、その後ターゲットクラスターでのみ書き込みを再開してください。

</Admonition>

### 直接データ転送\{#direct-data-transfer}

オフライン移行は、Zilliz Cloud クラスター間でデータを直接レプリケーションします。以下の特徴があります。

- **スキーマの保持**: ソースのスキーマが変更されずにターゲットクラスターに転送されます。

- **フィールドの変更なし**: 移行中にフィールド名の変更、データ型の変更、フィールド属性の変更はできません。

- **自動インデックス作成**: ターゲットクラスターのベクトルフィールドには AUTOINDEX が自動的に作成されます。

- **データの1回コピー**: オフライン移行は移行ジョブ中にソースクラスターからデータをコピーします。移行ジョブ完了後、ターゲットクラスターを新しい書き込みと同期し続けることはありません。

### カットオーバーの計画\{#plan-the-cutover}

オフライン移行を開始する前に、アプリケーションがソースクラスターへの書き込みを一時的に停止できるカットオーバーウィンドウを選択してください。データの欠落を防ぐには、以下の手順に従います。

1. 最終的な移行と検証のウィンドウの前に、ソースクラスターへの書き込みを停止します。

1. 移行ジョブを実行し、ジョブステータスが **成功** に変わるまで待ちます。

1. ターゲットクラスターのデータを検証します（例：エンティティ数の確認、最近挿入されたエンティティのサンプリング）。

1. アプリケーションの読み取りと書き込みをターゲットクラスターに切り替えます。

1. ターゲットクラスターでのみ書き込みを再開します。

移行データが完全であることを確認するまで、ソースクラスターは利用可能な状態に保ってください。
